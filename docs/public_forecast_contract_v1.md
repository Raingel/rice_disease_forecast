# Public Forecast CSV Contract v1 — Website Compatibility Baseline

> **Freeze only; no migration or new public API in this PR.** This is the
> currently observed external interface of
> `https://mycolab.pp.nchu.edu.tw/blast_forecast/`, not a proposed
> cross-model internal format. Any intentional future breaking change needs
> a new version, an adapter, and explicit website migration approval.

## Evidence and provenance

The website's read-only integration audit on **2026-11-01 (Asia/Taipei)**
recorded the source-to-browser flow and pinned GitHub `main` commit
`76bc679bb3225e24b2c7eaa45b4cdb4332a1792b`. The baseline
`tests/fixtures/public_contract_v1/snapshot_20261101.json` contains
**published** header snapshots from all nine daily models, the
`recent_daily_by_station/C0G910.csv` public header and a published row
for 2026-11-01, the `recent_summary.csv` public header, and complete
CSV records from five stations for each model. It was reduced from those
published CSVs, not generated by rerunning the refactored organizer.

The fixture is a **representative fixed sample**; it does not establish
whole-country equivalence for all dates, stations, or historical years.

## Three distinct public data products (must keep all three)

| Product | Source repository path | Consumer | Compatibility rule |
| --- | --- | --- | --- |
| Per-day, per-model | `rice_blast_prediction/data/YYYYMMDD_MODEL.csv` | `api/data.php?type=warning_map&schema=5&model=MODEL` | Retain filenames, station/date/value columns and source-native values |
| Per-station, multi-model | `rice_blast_prediction/recent_daily_by_station/STATION.csv` | `api/data.php?type=forecast_station&station=STATION` | Retain existing model columns and numeric/missing semantics |
| Seasonal summary | `rice_blast_prediction/recent_summary.csv` | `api/data.php?type=season_summary` | Retain existing 20-column v1 schema, counting/denominator rules and thresholds |

The website also reads the **separate**
`Raingel/weather_station_list` station master. The organizer's own
`recent_daily_by_station/station_list.csv` is **not** the current
website station-selector source.

### Stable keys and values

- Daily/station output station key is **`站號`**, parsed as a **string**:
  leading zeroes must survive; do not join by row index.
- Calendar-day key is **`日期`** in `YYYY-MM-DD`, with the site using
  Taiwan-local dates for forecast windows. Preserve original date meaning.
- Station labels `站名`, numeric `lat`/`lon`, old model columns, and
  their **native scales** are the public API. Column order varies across
  daily model files; consumers must match by header, not by position.
- The legacy seven disease model fields are
  `BlastGRU-TW`, `BlastDT2`, `BlastLSTLS`, `BLBTSLS`,
  `BlastTF`, `BlastGAT`, `BLASTAM`. The existing organizer
  also includes `EPIRICE_BLB` and `EPIRICE_LB`. The wide station CSV
  keeps BLB state columns under `EPIRICE_BLB_` and the three LB compact
  fields `EPIRICE_LB`, `EPIRICE_LB_intensity_active`,
  `EPIRICE_LB_status`. New fields may be added, but must not reinterpret
  or overwrite legacy fields.
- A valid model score **`0`** is *not* the same as missing.
  EPIRICE non-crop rows use **`-99`** in their public primary value
  with status `non_crop_period`; it is **not a risk prediction**.
  Missing values remain empty / NaN in CSV with their status as available.
  Existing status names include `ok`, `non_crop_period`,
  `missing_crop_calendar`, `missing_model_output`,
  `outside_model_duration`. A future internal v2 may normalize these
  to nullable values, but v1 must preserve its existing sentinel.
- EPIRICE primary output is `rateinf_new_infections`, an infection-flow
  model variable; do **not** present it as a calibrated 0–1 probability.
- The per-day BLB/LB CSVs carry detailed state/provenance fields. Preserve
  their public headers during this phase; only the LB **wide station
  projection** is compact.
- Model execution timestamps, source versions and weather hashes are
  provenance fields: do not silently recast PHP cache time as model time.

### Behavioral rules also part of the public contract

- `recent_forecast_organizer.py` loops the current `MODEL_FILES` order;
  the **first existing model** determines base station/date keys; normal
  models use **left joins**, EPIRICE_BLB/LB use validated **outer joins**.
  This can extend station/day coverage; a general rewrite to all-outer,
  all-inner or positional joins is not compatible.
- Relocated duplicate station/day records are resolved against the
  currently configured station coordinates, not arbitrarily kept first.
- Planthopper is a separate spatial forecast source and is joined to
  the per-station CSV on nearest coordinates; it has its own semantics.
- `crop_season_avg.py`: standard model high-risk-day threshold is
  `0.5`; `BlastGAT` is `0.23`; planthopper is positive `> 0.0`.
  Complete-year eligibility is assessed per model across **all dates**,
  not per station. It may use an independent planthopper average snapshot.
  Preserve this behavior, including the existing `_this_year` and
  `_avg` field names.
- Website presentation applies **additional distinct** legacy rules:
  homepage grid `0.2/0.4`, chart reference `0.5`, warning map
  `0.5/0.7`, and a BlastGAT-specific transformation in website PHP.
  None is a universal model calibration. These frontend rules are
  documented observations, not changed or tested directly by this PR.

## Phase 3A automated test scope

`tests/test_public_contract_v1.py` runs entirely offline:

1. Verify published daily headers, selected station/date keys and model IDs.
2. Use actual sampled daily CSV records for all nine models to run the
   *unchanged* organizer in a temporary directory (no planthopper HTTP).
   Compare all present C0G910 output fields **against the independently
   published station CSV row** (not merely against freshly generated data).
3. Distinguish valid model zero, EPIRICE non-crop `-99`, and
   missing-crop-calendar null without rewriting value/status semantics.
4. Lock the observed classic left-join versus EPIRICE outer-join behavior,
   and protect leading-zero station IDs.
5. Pin seasonal summary header ordering and 0.23 / 0.5 risk threshold
   boundaries using isolated synthetic cases.

```bash
python -m unittest discover -s tests -p 'test_public_contract_v1.py' -v
```

The PR CI also runs EPIRICE regression and relocated-station tests.
It never reads the real website or mutates published forecast CSVs.
A **separate website-side shadow test** is needed before *any* v1 to v2
deployment, comparing full station/date sets, missing masks, warning-map
matrices, historical summary denominators, and frontend risk profiles.

## Forward-compatible change policy

- **3A**: freeze legacy public interface and capture golden examples.
- **3B**: introduce normalized internal records, validators and model
  provenance; do not rewrite or remove the public CSVs.
- **3C**: adapt BLB/LB to normalized internal records with explicit v1
  compatibility writers; require exact published snapshot regression.
- **3D**: add coverage for multi-day historical and web API fixtures.
- **4**: introduce an authoritative upstream Model Registry; change legacy
  public products **only** through a reviewed compatibility adapter.
- **Website**: keep existing frontend HTML/JS/CSS and API v1 unchanged;
  v2 provider remains opt-in and requires separate deployment approval.

The pinned fixture is immutable: to update it for an intentional new
contract, record a new version and source revision, explain the migration,
and obtain review. Never automatically regenerate the baseline from the
new code under test.
